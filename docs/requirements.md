# Fuel — 要件定義・設計

最終更新: 2026-10-21

## 1. 目的

ダイエット中の人が、毎日の食事のカロリーとPFC（たんぱく質・脂質・炭水化物）を
**手間をかけずに**記録し、「今日あと何をどれくらい食べてよいか」をすぐ把握できるようにする。

栄養成分を調べて入力する手間が、食事記録が続かない一番の理由になる。
このアプリでは「食べたものを文章で書く（または写真を撮る）」だけで、Gemini AIが
品目ごとのカロリー・PFCを推定し、そのままその日の記録に追加できることを核にする。

## 2. 想定利用者・利用環境

- 開発者本人と身近な人（Firebase App Distributionでテスター配布）。将来的にPlay Store公開を視野に入れる
- Android端末（Android 7.0 / API 24以上。Flutterの既定値）
- 栄養計算の知識が無い人でも使えること

## 3. 機能要件

### F1. アカウント

| ID | 要件 |
|---|---|
| F1-1 | Googleアカウントでログインできる（Firebase Authentication） |
| F1-2 | 記録はクラウド（Firestore）に保存され、機種変更・再インストール後も引き継げる |
| F1-3 | ログアウトできる |
| F1-4 | アカウントと全データを削除（退会）できる。取り消せない操作なので確認を2段階で取る |
| F1-5 | 電波が無い場所でも手入力・お気に入りからの記録はでき、オンライン復帰時に同期される（Firestoreのオフライン永続化）。AI推定はオンライン時のみ |

### F2. プロフィールと1日の消費カロリー計算

初回ログイン時にプロフィール入力（オンボーディング）を必須にし、設定画面からいつでも変更できる。

| ID | 要件 |
|---|---|
| F2-1 | 性別・年齢・身長・現在の体重・運動頻度（活動レベル）を入力できる |
| F2-2 | 入力値から基礎代謝量（BMR）と1日の消費カロリー（TDEE）を計算して表示する |
| F2-3 | 目標（減量・維持・増量）とペース（週あたりの体重変化）から、1日の目標摂取カロリーを計算する |
| F2-4 | PFCバランスをプリセットから選ぶか、自分で比率（%）を指定でき、目標摂取カロリーからPFCそれぞれの目標グラム数を計算する |
| F2-5 | 目標摂取カロリーを手動で指定することもできる（指定した場合は計算値より優先） |
| F2-6 | 目標体重（任意）を設定できる |
| F2-7 | 入力中にBMR・TDEE・目標値がその場で再計算されて見える |

計算式は「5. 計算ロジック」を参照。

### F3. 食事の記録（AI推定）— このアプリの核

| ID | 要件 |
|---|---|
| F3-1 | 「きょう」画面の下部に、食べたものを書く入力欄を常に表示する（例:「牛丼並盛と味噌汁」「プロテイン1杯」） |
| F3-2 | 送信するとGemini AIが品目ごとに分けて、量の目安・エネルギー(kcal)・P・F・C(g)を推定して表示する |
| F3-3 | 推定結果は品目ごとにチェックで追加対象を選べ、値を修正してから追加できる |
| F3-4 | 食事区分（朝食・昼食・夕食・間食）を選んで、表示中の日付の記録へそのまま追加できる。区分の初期値は時刻から推定する |
| F3-5 | 食事の写真を撮る／アルバムから選ぶと、写真からも推定できる（文章との併用も可） |
| F3-6 | 食べ物と関係ない入力の場合は記録を作らず、その旨を表示する |
| F3-7 | AIの推定値であることを明示する（記録にも「AI推定」の印を付ける） |
| F3-8 | 1人あたり1日の推定回数に上限を設け（50回）、残り回数を設定画面で確認できる |
| F3-9 | 通信失敗・上限到達・サーバー未設定など、失敗理由ごとに次に取れる行動が分かる文言を出す |

### F4. 食事の記録（AI以外）

| ID | 要件 |
|---|---|
| F4-1 | 名前・量・kcal・P・F・Cを手入力して記録できる（栄養成分表示を見て入力する用途） |
| F4-2 | 手入力時、PFCからkcalを計算するボタンがある（P×4＋F×9＋C×4） |
| F4-3 | 最近食べたものから1タップで再記録できる（AIを呼ばないので上限を消費しない） |
| F4-4 | よく食べるものを「お気に入り」に登録し、1タップで記録できる。お気に入りは設定画面から管理（削除）できる |
| F4-5 | 記録の編集（値・量の倍率・食事区分）と削除ができる。削除は取り消せる（スナックバーの「元に戻す」） |

### F5. 1日のふりかえり（きょう画面）

| ID | 要件 |
|---|---|
| F5-1 | 表示中の日付の摂取カロリー／目標カロリーと残りカロリーをリング表示する（超過は色を変える） |
| F5-2 | P・F・Cそれぞれの摂取量／目標量（g）をバーで表示する |
| F5-3 | 記録を食事区分ごとにまとめて表示し、区分ごとの小計kcalを出す |
| F5-4 | 前日・翌日へ移動でき、日付をタップするとカレンダーから選べる。今日以外を表示中は「今日へ」戻れる |
| F5-5 | 画面を開いたまま日付が変わった場合、今日を表示していたなら復帰時に新しい今日へ切り替える |

### F6. 履歴

| ID | 要件 |
|---|---|
| F6-1 | 直近7日／30日の摂取カロリーを棒グラフで表示し、目標カロリーを線で重ねる |
| F6-2 | 期間の平均摂取カロリー・平均PFC（g）・実際のPFC比率（%）を目標と並べて表示する |
| F6-3 | 日ごとの合計一覧を表示し、タップするとその日の「きょう」画面を開く |
| F6-4 | 記録の無い日は平均の計算から除く（記録を付け忘れた日が平均を下げないように） |

### F7. 体重

| ID | 要件 |
|---|---|
| F7-1 | 日付ごとに体重を1件記録できる（同じ日に再入力したら上書き） |
| F7-2 | 体重の推移を折れ線グラフで表示し、目標体重があれば線で重ねる |
| F7-3 | 最新の体重・BMI・目標体重までの差・前回比を表示する |
| F7-4 | 最新の体重記録を「現在の体重」としてプロフィールへ反映し、消費カロリー・目標値の計算に使う |
| F7-5 | 記録の削除ができる |

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | Gemini APIキーはアプリに埋め込まない。Cloud Functions（Secret Manager）からのみ使う（aimaruで、`--dart-define`で埋めたキーはAPKから抽出できると判明した反省） |
| セキュリティ | Firestoreのデータは本人しか読み書きできない。レート制限のカウンタはクライアントから書き換えられない場所（`aiUsage/{uid}`）に置く |
| セキュリティ | AIへのプロンプトはサーバー側で組み立てる。クライアントが任意のプロンプトを送れる設計にすると、関数が「誰でも使える無料のGemini中継」になってしまう |
| セキュリティ | 入力値の範囲はアプリ・Cloud Functions・セキュリティルールの3か所で同じ上限を使う（`docs/requirements.md` 6章） |
| 信頼性 | AIの応答は構造化出力（JSONスキーマ指定）で受け、サーバー側でも数値の範囲を検証・丸めてから返す。解釈できない応答から記録は作らない |
| 信頼性 | ストリームを使う画面は、ローディング・エラー・データの3状態を必ず扱う（無限ローディングにしない） |
| コスト | AI推定は1人1日50回まで。Cloud Functionsの最大インスタンス数を絞る |
| 性能 | AI推定の待ち時間中はローディングを表示し、二重送信できないようにする |
| 保守性 | ロジック（計算・集計・応答の解釈）は純粋関数に切り出して単体テストする。画面はFirebaseを差し替えてウィジェットテストする |
| アクセシビリティ | 文字サイズを大きくしてもレイアウトが崩れない（結合テストで検査） |
| 法令・注意書き | 推定値は目安であり、医療上の助言ではない旨をアプリ内に記載する |

## 5. 計算ロジック

### 5.1 基礎代謝量（BMR）— Mifflin-St Jeor式

```
男性: BMR = 10 × 体重(kg) + 6.25 × 身長(cm) − 5 × 年齢 + 5
女性: BMR = 10 × 体重(kg) + 6.25 × 身長(cm) − 5 × 年齢 − 161
```

国際的に最も広く使われ、ダイエットアプリでの標準的な選択肢であるためこれを採用する
（国立健康・栄養研究所の式との差は一般的な体格で数十kcal程度）。

### 5.2 1日の消費カロリー（TDEE）

`TDEE = BMR × 活動係数`

| 運動頻度（活動レベル） | 係数 |
|---|---|
| ほとんど運動しない（デスクワーク中心） | 1.2 |
| 軽い運動（週1〜3回） | 1.375 |
| 適度な運動（週3〜5回） | 1.55 |
| 活発な運動（週6〜7回） | 1.725 |
| 非常に活発（毎日の激しい運動・肉体労働） | 1.9 |

### 5.3 目標摂取カロリー

体脂肪1kg ≒ 7,200kcal として、週あたりのペースを1日あたりの増減に換算する。

```
1日の増減 = ペース(kg/週) × 7200 ÷ 7
減量: 目標 = TDEE − 1日の増減   （ペース: 0.25 / 0.5 / 0.75 kg/週）
維持: 目標 = TDEE
増量: 目標 = TDEE + 1日の増減   （ペース: 0.25 / 0.5 kg/週）
```

- 目標は10kcal単位に丸める
- 減量時、目標が基礎代謝量を下回る場合は**基礎代謝量まで引き上げる**（極端な制限を避けるため）。引き上げた場合は画面にその旨を表示する
- 手動で目標カロリーを指定した場合はそれを優先する（1,000〜5,000kcal）

### 5.4 PFC目標

目標摂取カロリーに対する比率（%）からグラム数を出す。たんぱく質・炭水化物は1gあたり4kcal、脂質は9kcal。

```
P(g) = 目標kcal × P% ÷ 4
F(g) = 目標kcal × F% ÷ 9
C(g) = 目標kcal × C% ÷ 4
```

| プリセット | P | F | C | 用途 |
|---|---|---|---|---|
| バランス（標準） | 20% | 25% | 55% | 日本人の食事摂取基準（2025年版）の目標量の範囲内 |
| 高たんぱく | 30% | 25% | 45% | 筋肉を落とさず減量したい |
| ローファット | 25% | 15% | 60% | 脂質を抑えたい |
| ローカーボ | 30% | 40% | 30% | 糖質を抑えたい |
| カスタム | 任意 | 任意 | 任意 | 各5〜70%、合計100% |

### 5.5 1日の集計

- 摂取量 = その日の記録の合計（kcal・P・F・C）
- 残り = 目標 − 摂取（マイナスは超過として表示）
- 実際のPFC比率 = (P×4, F×9, C×4) ÷ その合計（kcalの値ではなく三大栄養素から計算する）

### 5.6 BMI

`BMI = 体重(kg) ÷ 身長(m)²`（小数1桁）

## 6. 入力値の範囲（アプリ・Functions・ルール共通）

| 項目 | 範囲 |
|---|---|
| 年齢 | 15〜100（整数） |
| 身長 | 120〜220 cm |
| 体重・目標体重 | 30〜250 kg |
| 手動の目標カロリー | 1,000〜5,000 kcal |
| PFC比率 | 各5〜70%（整数）、合計100% |
| 記録の名前 | 1〜60文字 |
| 記録の量 | 0〜40文字 |
| 記録のエネルギー | 0〜5,000 kcal |
| 記録のP・F・C | 各0〜500 g |
| AIへの文章 | 1〜500文字（写真がある場合は0文字でも可） |
| AIへの写真 | JPEG / PNG / WebP / HEIC、base64で約4MBまで（端末側で1280pxに縮小して送る） |
| AIの推定品目数 | 最大20品目 |

## 7. データモデル（Firestore）

```
users/{uid}                          … 名前・メールアドレスは保存しない（必要な表示はAuthから読む）
  updatedAt : timestamp
  profile: {                         … 未入力ならフィールド自体が無い（オンボーディングへ）
    sex             : 'male' | 'female'
    age             : int
    heightCm        : number
    weightKg        : number          … 最新の体重記録を反映（F7-4）
    activityLevel   : 'sedentary' | 'light' | 'moderate' | 'active' | 'veryActive'
    goal            : 'lose' | 'maintain' | 'gain'
    weeklyRateKg    : number          … 0, 0.25, 0.5, 0.75（維持は0）
    pfcPreset       : 'balanced' | 'highProtein' | 'lowFat' | 'lowCarb' | 'custom'
    proteinRatio, fatRatio, carbsRatio : int（%）
    targetWeightKg  : number | null
    customTargetKcal: int | null
  }

users/{uid}/meals/{entryId}         … 食事の記録1品＝1ドキュメント
  date      : 'YYYY-MM-DD'（端末のローカル日付。タイムゾーンのずれを避けるため文字列キー）
  mealType  : 'breakfast' | 'lunch' | 'dinner' | 'snack'
  name      : string
  amount    : string（空文字可）
  calories, protein, fat, carbs : number
  source    : 'ai' | 'manual' | 'favorite' | 'recent'
  createdAt : timestamp

users/{uid}/weights/{YYYY-MM-DD}    … 1日1件（ドキュメントID＝日付で上書き）
  date      : 'YYYY-MM-DD'
  weightKg  : number
  updatedAt : timestamp

users/{uid}/favorites/{favoriteId}
  name, amount, calories, protein, fat, carbs, createdAt

aiUsage/{uid}                        … AI推定の回数制限。Cloud Functionsだけが書く
  date  : 'YYYY-MM-DD'（Asia/Tokyo）
  count : int
```

日付を文字列キーにしているのは、深夜の記録が端末とサーバーのタイムゾーン差で
前後の日にずれるのを避けるため（「何日の食事か」は利用者の感覚の日付が正）。

## 8. Cloud Functions

| 関数 | 種別 | 役割 |
|---|---|---|
| `estimateNutrition` | onCall（要ログイン） | 文章・写真からPFCを推定。入力検証 → レート制限（トランザクション） → サーバー側でプロンプトを組み立ててGemini呼び出し（構造化出力） → 応答を検証・正規化して返す |
| `deleteAccount` | onCall（要ログイン） | `users/{uid}`（サブコレクション含む）と`aiUsage/{uid}`を再帰削除し、Authのユーザーを削除する |

- リージョンは `asia-northeast1`（東京）。アプリ側も同じリージョンを指定して呼ぶ
- モデルは `gemini-flash-lite-latest`（無料枠に余裕があるため。aimaruと同じ判断）。temperatureは低め（0.2）にして同じ入力で値がぶれにくくする
- 失敗時は`logger.error`にGeminiのステータス・モデル名・エラー本文を残す（APIキーは出さない）
